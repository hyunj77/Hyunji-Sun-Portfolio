# NUMBERING 리디자인 — 프로젝트 규칙

웹디자이너 포트폴리오 작품(기존 numberingwebsite.com 리디자인). 피그마 시안을 **그대로** 구현한다.
Figma: https://www.figma.com/design/ZBRkB1QpsnAXKbvQCNz8Ao (node 49-124, Desktop 1920)

## 최우선 원칙 — 시안 100% 반영
- 시안에 없는 요소·효과(그림자, 호버, 트랜지션, 애니메이션 등)·색상·문구·이미지·아이콘을 **임의로 추가/삭제/변경하지 않는다.** 필요해 보이면 먼저 사용자에게 묻는다.
- 개선점이 보여도 고치지 말고 **제안으로만** 알린다.
- 애매하면 추측하지 말고 먼저 묻는다.
- 크기, 간격, 폰트 크기, 줄 간격, 자간, 색상, 투명도, 이미지 비율, 라운드, 테두리는 **피그마 값 그대로**. 추정한 값은 어디인지 반드시 보고한다.
- 데스크톱 1920 시안과 픽셀 단위로 일치시킨다.

## 기술 스택 / 구조
- 순수 HTML / CSS / JS. 프레임워크·빌드 도구 금지.
- `index.html`은 프로젝트 루트 바로 아래.
- `css/` tokens.css, reset.css, base.css, components.css, sections/섹션별.css
- `js/` 섹션·기능별 파일 · `assets/` images, icons, fonts
- 사용자가 미리 둔 폴더(BEST/, Store/, 컬렉션/, 네비게이션 바/, 넘버링 로고/, *.jpg)는 **수정/삭제하지 않는다.** 구현은 `assets/`의 시안 자산만 사용한다.

## 코드 품질
- 시맨틱 태그(header, nav, main, section, footer), 의미 있는 alt.
- BEM 네이밍. 반복 요소(CTA 링크, 원형 버튼, 상품 카드, 마퀴)는 공통 컴포넌트로 재사용.
- 색상·폰트·간격은 `css/tokens.css`의 CSS 변수로. 매직 넘버 금지.
- 섹션 구분 주석은 간결하게.

## 폰트
- **Inter만 Pretendard로 대체**(영문). 나머지는 피그마 원본: Laila, KoHo, 42dot Sans, Montserrat, Inria Serif.
- 한글 글리프가 없는 폰트(Laila/KoHo/Montserrat/Inria Serif)에 지정된 한글만 **Noto Sans KR**로 표시.
  `font-family: '원본폰트', 'Noto Sans KR', sans-serif` 순서로 쓴다(통째로 교체 금지).
- Noto Sans KR은 400·500·800 정적 파일을 `@font-face`로 굵기별 지정, `font-synthesis: none`(faux bold 금지).
- 42dot Sans(Collection 설명)은 변경하지 않는다.
- 폰트 파일은 CDN 금지, `assets/fonts/`에 두고 `@font-face`로 연결. 실제 쓰는 굵기만 로드.
- 한글 폭 차이로 줄바꿈/높이/잘림이 달라지면 글자 크기를 임의 조정하지 말고 사용자에게 보고.
- Pretendard 대체 부분은 스크린샷 비교 후 line-height/letter-spacing을 피그마 값에 맞게 조정.

## 이미지 / 아이콘
- 피그마 자산 URL은 만료되므로 `assets/images`, `assets/icons`에 로컬 저장해 사용. 아이콘은 가능하면 SVG. 시안 아이콘을 다른 것으로 바꾸거나 새로 만들지 않는다.
- 로고/헤더 아이콘 PNG는 검은 배경이 포함된 원본 그대로 쓴다(시안 동일).

## 반응형
- 3구간: 데스크톱 ≥1200 / 태블릿 768~1199 / 모바일 ≤767. **데스크톱(1920 포함)은 그대로 둔다(사용자 지시).**
- 태블릿·모바일은 이제 시안이 있다(아래). 이전의 "시안 없음 [추정]" 태블릿/모바일 규칙(햄버거 드로어, 모바일 BEST 한 장씩 자동 넘김, SNS 3칸 슬라이더 등)은 모두 이 시안으로 **대체·삭제**됨.

### 사용자 지시(시안 외 효과) — 고정 헤더 (그대로 유지)
- **헤더는 화면 위에 고정**: `.site-header`를 `position: fixed`로(이전 `absolute`). 맨 위(스크롤 0)는 높이 74px, 로고/GNB/아이콘의 위치와 크기는 시안 그대로, `z-index: 10`. **스크롤 시(`.is-scrolled`)에는 높이 56px**(`--header-h-scrolled`, 사용자 지시). Hero 레이아웃과 아래 섹션 위치는 변하지 않음(스크롤 0에서 모든 섹션 요소 위치·크기·스타일 값이 수정 전과 같음). **이벤트 바(마퀴)는 Hero 안에서 스크롤과 함께 움직이며 고정하지 않는다.**
- **스크롤 10px 이상이면 배경 검정 80% + 높이 56px**, 맨 위로 돌아오면 다시 투명 + 74px. 배경과 높이는 같이 0.3초(`--motion-duration`, easing `ease` [추정]) 전환. 글자/아이콘/로고의 크기는 그대로. 색은 `tokens.css`의 **`--header-bg-scrolled`(`rgb(0 0 0 / 0.8)`)**, 높이는 **`--header-h-scrolled`(56px)** 한 곳에서 조절.
- **줄어든 헤더 안의 세로 정렬(사용자 선택 B, 스크롤 상태에서만)**: 로고(`--header-logo-h`)와 아이콘(`--header-icon-size`) 박스는 `top: calc(50% − 높이/2)`로 헤더 정중앙, GNB 글자는 `--header-gnb-ink-shift: 4px`만큼 내려 글자 잉크 중심을 헤더 중심에 맞춤. **[추정] 4px**: GNB 글자가 28px 박스의 윗부분에 놓여 글자 중심이 박스 중심보다 4px 위(실측). 맨 위(스크롤 0)의 `top` 값(`--header-logo-y` 등)은 시안 그대로이고(계산값 동일, `calc(50% + 시안 top − 헤더 높이/2)` 형태로 써서 높이가 줄어드는 전환 중에도 요소가 헤더 중심을 따라감 — 전환 중 로고 중심과 헤더 중심의 차이 최대 0.01px). 높이와 로고/GNB/아이콘의 `top`을 같은 시간·같은 easing으로 전환해 중간 프레임에서도 정렬이 어긋나지 않음(`top` 기반, `transform` 아님). 1200px 미만에서는 GNB가 메뉴 패널이라 GNB 내림 값은 적용하지 않음.
- **모바일 메뉴 패널**: `top: 100%`(이전 `var(--header-h)`)로 헤더 높이를 따라가 틈/겹침이 없다.
- **구현**: `js/header.js`(별도 파일, `nav.js`와 클래스가 달라 충돌 없음). `window.scrollY >= 10`일 때 `.is-scrolled`. 스크롤 이벤트는 `passive` + `requestAnimationFrame`으로 묶고, 상태가 바뀔 때만 클래스 토글. 로드 직후와 `pageshow`에서도 한 번 검사. 임계값 10px은 `js/header.js`의 `SCROLL_THRESHOLD`(문서용 `--header-scroll-threshold`와 같아야 함).
- **모바일 메뉴**: 스크롤된 상태(`.is-scrolled`)에서 메뉴가 열리면(`.is-menu-open`) 헤더 배경을 패널과 같은 불투명 검정(`--color-black`)으로 맞춤. 맨 위에서 열면 지금처럼 헤더는 투명 + 패널 검정.
- **`prefers-reduced-motion: reduce`**: 헤더의 모든 전환(배경, 높이, 로고/GNB/아이콘 위치)을 제거(즉시 바뀜). SNS 슬라이드(0.4초)와 마퀴는 모션 설정과 무관하게 그대로 동작(사용자 지시).
- **알려진 한계(사용자 승인)**:
  - 스크롤 0에서도 `fixed` 헤더는 별도 렌더링 레이어가 되어 GNB/LANGUAGE 글자 가장자리 안티앨리어싱이 미세하게 다르다(1920×1080 기준 약 2,700px, 최대 147, 범위 x 750~1683 / y 26~41). 로고와 헤더 밖은 0px. 위치와 크기는 같다. (`sticky`, `translateZ(0)`도 같음 → `fixed` 항상 적용으로 결정)
  - [해결됨] 로고·검색·계정 PNG에 불투명 검정 배경이 구워져 있어 흰 섹션 위 80% 검정 헤더에서 어두운 사각형으로 보이던 문제(이전 사용자 결정 (a)로 에셋을 안 바꿨었음)를 사용자 요청으로 해결: 흑백 PNG의 밝기를 투명도로 바꿔 **글씨/선만 흰색, 배경 투명**인 `assets/images/hero/logo-transparent.png`(216×36), `assets/icons/search-transparent.png`, `account-transparent.png`(418×418)를 새로 만들어 교체(선 가장자리의 부드러움 유지). 원본 `logo.png`·`search.png`·`account.png`는 파일로 남아 있음(사이트는 안 씀). 흰 구간에서 로고·아이콘 박스 모서리 색이 헤더 배경 `rgb(51,51,51)`과 동일함을 측정으로 확인. 장바구니/메뉴 PNG는 원래 투명. 로고 원본이 216px라 고해상도 화면에서는 약간 흐릿할 수 있음(더 큰 원본이 있으면 같은 방식으로 재제작 가능). 불투명도는 `--header-bg-scrolled` 한 곳.

### 사용자 지시(시안 외 효과) — 호버 하이라이트(Codrops Adsila): GNB, Collection 탭 (그대로 유지)
- **출처**: Codrops "Inspiration for Menu Hover Effects"(https://tympanus.net/Development/MenuHoverEffects/, 소스 github.com/codrops/MenuHoverEffects)의 **Adsila**. 사용자가 글의 효과 중 이것을 골랐고, 색은 **반투명 흰색**으로(Adsila 원본도 불투명도 0.3). (검토한 다른 효과: Inola 가로지르는 줄, Salal 블록, Dustu 블록 스윕, Tsula 깜빡이는 커서, Ama/Mohe/Yona 글자별 애니메이션(anime.js) — 쓰지 않음.) 그 전에 시도한 한 줄 밑줄, 위·아래 선, 방사형 빛은 모두 이 효과로 **교체/제거**됨.
- **GNB 메뉴(Shop, About, Stores, Membership, Help, Review)**: 마우스를 올리면 글자 뒤 **아래쪽 절반에 반투명 흰색(30%) 띠가 왼쪽에서 오른쪽으로 깔린다**(`::before`, `transform: scaleX(0 → 1)`, 원점 왼쪽). 마우스를 치우면 **왼쪽으로 접힌다**(원점이 계속 왼쪽). 띠 폭 = 글자 폭 + 양옆 0.35em(16px 글자면 5.6px씩), 높이 = 글자 박스의 50%(9.5px). 글자 색·크기·위치는 그대로, 띠는 글자 뒤(`z-index: -1`, 글자 `<span class="gnb__text">`는 `isolation: isolate`)라 레이아웃·헤더 높이에 영향 없음. 스크롤된 56px 헤더와 1200px 미만 메뉴 패널에서도 같음.
- **Collection 탭(Heart, Ribbon, Star, Chunky, Initials)**: **선택 안 된 탭**에 올리면 글자가 회색(`#a7a6a5`) → 흰색으로 바뀌고(0.3초) 같은 띠가 깔린다. **활성 탭은 띠가 그대로 남아 있다**(사용자 지시 "밑줄이 그대로 남아있으면"): 처음 활성인 Heart에도 띠가 있고, 다른 탭을 클릭하면 그 탭의 띠가 남고 이전 탭의 띠는 접힌다(마우스를 치워도 유지). (호버만 하는 GNB에는 선택 상태가 없어 호버할 때만 띠.)
- **값(tokens.css)**: `--hover-bar-color: rgb(255 255 255 / 0.3)`, `--hover-bar-height: 50%`, `--hover-bar-extend: 0.35em`, `--hover-bar-duration: 0.5s`, `--hover-bar-ease: cubic-bezier(0.2, 1, 0.3, 1)` — 높이·확장·시간·이징은 Adsila 원본 값 그대로. 탭 글자색 전환만 `--motion-duration`(0.3초).
- **마우스가 있는 기기(`@media (hover: hover)`)에서만** 호버 적용(터치 기기는 효과 없음), 키보드 포커스(`:focus-visible`)에서는 같은 효과(접근성). `prefers-reduced-motion: reduce`이면 전환 없이 즉시 바뀜.
- 호버하지 않은 기본 화면은 이전과 픽셀 동일(단, 활성 탭 Heart 뒤에 띠가 추가됨).

  3. 사용자가 "다음"이라고 하면 다음 섹션 진행
